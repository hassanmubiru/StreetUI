# StreetUI 2.2.0 — DevTools Report (Phase 1)

**Date:** 2026-09-29
**Scope:** the full interactive DevTools milestone.
**Hard constraint honored:** the **production runtime never imports DevTools.**
DevTools is a separate, opt-in surface; nothing on the app build / SSR / test path
pulls it in.

---

## 1. What was built

Phase 1 turns the previously headless DevTools inspectors into a complete,
interactive developer surface without adding a second reactive system, a second
renderer, or any browser-only dependency. Two kinds of work:

**New headless inspectors (4)** added to `packages/devtools/src/`:

- `inspectEvents` (event wiring / listener inventory)
- `inspectSignalGraph` (signal → derived → effect dependency graph)
- `inspectHydration` (SSR → hydrate adoption detail)
- `inspectMutation` (mutation / write-primitive activity)

These extend `DevToolsSnapshot` / `Sources` with `events`, `signalGraph`,
`hydration`, `mutations`, and `signalsById`, and are all wired through
`index.ts`.

**Interactive host (`interactive.ts`)** exposing `renderInteractiveDevTools`, a
`DEVTOOLS_TABS` catalogue of **12 panels**, an embedded-JSON snapshot, a
dependency-free vanilla-JS controller, a pull-based refresh hook
(`window.__STREETUI_DEVTOOLS_REFRESH__`), and a `window.__StreetUIDevTools`
handle.

## 3. Self-containment (the load-bearing constraint)

- **The runtime does not import DevTools.** The DX self-containment check
  (`dx-audit.json`) confirms the framework public entries (`index` / `server` /
  `testing`) import neither `esbuild` nor any `@streetui/*` specifier; DevTools is
  reached only when a developer explicitly renders it.
- The interactive controller is **dependency-free vanilla JS**. There is no React,
  Vue, or other UI runtime behind the panels — consistent with the mission's
  no-second-framework rule.
- The refresh model is **pull-based**: the host calls the exposed refresh hook;
  DevTools does not install itself into the reactive system or the render loop.

## 4. Testing — and what is *not* claimed

The `devtools` package now runs **85 tests** (was 63; **+22**), across 12 files.

**Honest scope of those tests:** they are **Node-only**. They validate the
controller's parse-validity (the embedded controller is checked via
`new Function` for syntactic correctness) and that the snapshot JSON is embedded
**safely and faithfully** (XSS-escaped, structurally intact). They do **not**
claim a browser render of the panels — no browser is available (see the
Environment Report). The interactive surface is proven to be *well-formed and
safe to ship*; it is not proven to have been *painted in a browser*.

The `Performance` panel surfaces observer counts and is explicitly labelled **not
a production profiler** so its numbers are never mistaken for wall-clock
framework performance.

## 5. What remains for 2.3

Drive `renderInteractiveDevTools` in a real browser to validate panel rendering,
interaction, and the refresh hook end-to-end. That is currently BLOCKED only by
the absence of a browser binary, not by any missing code.
