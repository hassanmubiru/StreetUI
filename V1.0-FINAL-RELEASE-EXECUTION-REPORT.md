## 3. What was built

### 3.1 Unified `packages/streetui/` package (public: `streetui`)

The primary consumer-facing artifact. A user runs `npm install streetui` and
gets the complete framework — all 17 internal `@streetui/*` modules bundled in,
no transitive `@streetui/*` dependencies to install. One runtime dependency:
`esbuild@0.24.2` (needed by the bundled CLI's `build` command at runtime).

**Entry points:**
- `.` (`src/index.ts`) — full framework: reactivity, DSL, compiler, graph,
  runtime, events, scheduler, DOM adapters, renderer (incl. SSR + hydration),
  router, forms, context, i18n, devtools, `defineConfig`, `VERSION`
- `./server` (`src/server.ts`) — SSR subset: `renderToString`, `serializeState`,
  `readState`, `STATE_MARKER_ATTR`, `ServerDOMAdapter`, `VERSION`
- `./testing` (`src/testing.ts`) — test helpers: `render`, `findByRole`,
  `waitFor`, `renderServerThenHydrate`, `VERSION`

**Bin:** `streetui` → `dist/bin.js`, `create-streetui` → `dist/create-bin.js`

**Build mechanism:** tsup with `noExternal: [/^@streetui\//]` (esbuild inlines
all internal JS) and `dts: { resolve: [/^@streetui\//] }` (rollup-dts inlines
internal `.d.ts`). A `tsconfig.build.json` maps `@streetui/*` → source
(`../*/src/index.ts`) so rollup-dts resolves types from source rather than
pre-built `.d.ts` files — this prevents duplicate declarations (two structurally
identical but nominally distinct classes). A post-build `scripts/scrub-dts.mjs`
rewrites residual `@streetui/*` mentions in JSDoc comments and fails loudly if
any real `import`/`require` from an internal package survives bundling.

**Packed tarball:** `dist-tarballs/streetui-1.0.0.tgz` — 531 KB, 58 files
(`dist/` + `templates/` + `README.md` + `LICENSE` + `package.json`).

### 3.2 Internal `@streetui/*` packages (also published)

All 17 remain published individually for advanced consumers who want fine-grained
imports. They are the internal implementation modules that `streetui` bundles.
Nothing changed in their source.

### 3.3 Examples

All 7 examples (`basic-app`, `streetui-account`, `streetui-data`, `streetui-docs`,
`streetui-full-app`, `streetui-showcase`, `streetui-ssr`) depend on
`"streetui": "workspace:*"` exclusively — no individual `@streetui/*` imports.
All 7 build and typecheck. 5 of 7 pass all tests; 2 (`example-account`,
`example-data`) have tests that require a live HTTP API and are pre-existing
failures, not regressions.
