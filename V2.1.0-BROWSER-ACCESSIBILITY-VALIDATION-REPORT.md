## 1. What 2.1 was for

StreetUI 2.0 is already a complete application framework. 2.1 is a **validation
phase, not a feature phase**: its purpose is to validate the existing framework
under real conditions and to establish a reproducible, fair measurement
methodology. No new large framework subsystem was added. The single additive
convenience shipped (`renderDevToolsReport`) composes existing pieces and adds no
new capability.

**Overriding rule honored throughout: no result is fabricated.** Where a
capability (real browser, assistive technology, competitor browser benchmarks,
public registry) is unavailable in this environment, it is reported as `BLOCKED`
with the exact reason — never simulated, never substituted with happy-dom, never
filled in with numbers from another benchmark.

## 7. First usable DevTools interface (§23)

Shipped `renderDevToolsReport(compiled, sources?, options?)` in
`@streetui/devtools`, re-exported through the public barrel. It is a thin,
**additive** convenience — exactly:

```
renderDevToolsReport(compiled) ≡ renderDevToolsHTML(createDevTools(compiled).snapshot)
```

It inherits every property of the pieces it composes: DOM-free (runs in Node, a
worker, or a test), non-mutating and non-instrumenting (DevTools pulls, never
pushed), zero production cost (nothing in the runtime imports it). Three new tests
prove it emits a complete self-contained `<!doctype html>` document, equals the
two-piece composition, and is non-mutating across re-runs. A generated demo lives
at `benchmarks/results/v2.1/devtools-demo.html`.

**Honest scope:** it produces markup. Pixel-correct rendering, screen-reader
accessibility, and 60 fps in a real browser are **not** claimed and **not**
verified here — the browser/AT gates are BLOCKED.

  metadata/i18n/a11y/SSR+hydration together).
- SSR correctness & stability: **validated** — byte-identical to v1.6.
- Client-bundle boundary: **validated** — no server/CLI/testing/devtools leak.
- Release consumability: **validated offline** (tarball + generated app).
- Real browser, AT, and competitor comparison: **BLOCKED**, reported honestly
  with exact reasons — not simulated, not fabricated, not ranked.

The strongest honest claim 2.1 supports: StreetUI is a functionally complete,
SSR-byte-stable, cleanly tree-shakeable, offline-consumable framework at 2.1.0.

performance remain **unverified in this environment** and are labelled BLOCKED —
