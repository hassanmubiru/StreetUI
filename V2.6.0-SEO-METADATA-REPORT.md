# StreetUI 2.6.0 — SEO / Document-Metadata Validation Report

**Phase 6 of the 2.6.0 "Production Website Validation" mission.**
Subject under test: the official StreetUI website, `examples/streetui-website/`, built
entirely in StreetUI and served through the single public `streetui` package
(entry points `.`, `/server`, `/testing`).

Scope: validate that the website emits correct, per-route document metadata on the
server, that the client applies and updates that metadata on navigation, and that a
server render is adopted on hydration without duplicating head tags. This phase also
discharges a mandated **correction** of an inaccurate claim in the 2.5 findings.

Environment: Node v22.23.2 sandbox (no browser, no AT, npm registry blocked). All
assertions below are made through the framework's own public API and the `happy-dom`
test environment — **no browser crawler, social-card scraper, or search-engine indexer
was run here**; those are out-of-process consumers verified in the authoritative
environment and are explicitly out of scope for this file (see "Engine boundary").

---

## 1. Headline correction (mandated)

The 2.5 website **declared no `head()` calls at all.** No route emitted a `<title>`,
description, canonical URL, Open Graph, Twitter card, or robots directive. The
`V2.5.0-FRAMEWORK-FINDINGS.md` document listed "head metadata" among the capabilities
the website exercised; that was inaccurate. Document metadata was a genuine **coverage
gap**, not an exercised capability.

That correction has been applied to `V2.5.0-FRAMEWORK-FINDINGS.md` (a dated
"Correction (2.6)" note now sits in the "What was explicitly NOT found" section and
points here). 2.6 closes the gap by adding a real metadata layer to the website and, in
doing so, surfaced a legitimate framework dogfooding finding (F-7, below).

---

## 2. What the website now emits

Metadata is declared with StreetUI's own first-class `head()` primitive (shipped in
2.0) — the same semantic-graph + handler model as the rest of the framework, not a
bolt-on. The source of truth is `examples/streetui-website/src/metadata.ts`.

Every indexable route emits a complete document head:

- `<title>` — the page's own title suffixed with the site name (`"About · StreetUI"`).
- `<meta name="description">` — the page's description, or the site default when a page
  supplies none.
- `<link rel="canonical">` — `SITE.baseUrl + path`.
- `<meta name="robots">` — `index,follow` by default; `noindex` on the 404 page and on
  unknown docs/blog routes.
- `<meta name="theme-color">`, `<link rel="icon">`, `<meta name="viewport">`,
  `<meta charset>` — site-wide document defaults.
- Open Graph: `og:site_name`, `og:type` (`website`), `og:title`, `og:description`,
  `og:url`, `og:image`.
- Twitter: `twitter:card` (`summary_large_image`), `twitter:title`,
  `twitter:description`, `twitter:image`.

`SITE` constants: name `StreetUI`, baseUrl `https://streetui.dev`, default title
`StreetUI — a semantic-graph UI framework`, theme-color `#0b0d10`, OG image
`https://streetui.dev/og-card.png`.
