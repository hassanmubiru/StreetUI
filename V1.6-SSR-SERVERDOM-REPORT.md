## What changed, and why it is safe

### §4/§5 — Measured the bottleneck first
Profiling `renderToString` for the 10k-row `/users` app (150,050 nodes: 80,029 elements + 70,021 text) reproduced the split: **mount ≈ 61%, serialize ≈ 32%, escape ≈ 4%.** Mount dominates.

A ServerDOM census of the built tree found the waste precisely:

| store | elements that use it | empty allocations per render |
| --- | --- | --- |
| `attributes` Map | 80,028 / 80,029 | keep eager |
| `properties` Map | **1** / 80,029 | **80,028 wasted** |
| `style` (ServerStyle + Map) | **0** / 80,029 | **80,029 wasted** |

Every `ServerElement` eagerly allocated a `properties` Map **and** a `ServerStyle` (which holds its own Map), even though ~0% of elements use them → **~240,000 wasted allocations per `/users` render**, all in the dominant mount phase.

### §6/§8 — The optimization (reuse the model, don't replace it)
`properties` and `style` became **lazily allocated**: backing fields `_properties`/`_style` default `null`; the public `properties`/`style` getters allocate on first *write*; `serializeAttributes` reads the raw backing fields so a *read* never allocates. This is a change to *when* the existing objects are created — **not a separate SSR semantics engine** (§6) and **not a compiler change** (§7).

### Result
- **Mount −20%** (112.20 → 89.48 ms median; same-process A/B ~112 → ~85 ms), **total render −12%** (183.04 → 160.62 ms).
- **Byte-identical output** — SHA-256 matches on all 5 routes (§11), and the v1.4 serialize A/B still shows 1.66× byte-identical (§10). An unset store serialized to nothing before, and a `null` store is skipped the same way.
- **No retention** (§14/§15): heap steady across 50/100/200 renders.
- **12 new locked-in tests** (§8) in `@streetui/dom`: byte identity for simple text, attributes, nested elements, special characters, boolean attributes, void elements, Unicode, a 2,000-row static subtree; plus "reading never allocates / writing allocates on demand / explicit attribute wins over property".

- **§16/§17** hydration 0-node invariant and every client gate still PASS; client runtime untouched.
