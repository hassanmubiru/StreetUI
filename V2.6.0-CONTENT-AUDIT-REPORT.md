# StreetUI 2.6.0 — Website Content / Documentation Audit

**Phase 7 of the 2.6.0 mission.** Rule: every API the website documents must exist in
the published `streetui` package. **Invent nothing.**

Method: the website's documentation is data-driven (`examples/streetui-website/src/content.ts`
— 18 doc sections, an API-reference listing, examples, changelog, blog). Every API name
in that content — in the explicit API-reference listing, in the runnable code samples,
and in the prose — was cross-checked against the **actual exported surface of the built
package** at `packages/streetui/dist/` (version 2.5.0, held), enumerated by importing
`dist/index.js`, `dist/server.js`, `dist/testing.js` and by reading the emitted `.d.ts`
builder interfaces (DSL methods live in the shared type chunk, not in `index.d.ts`
directly).

Authoritative surface sizes: main entry 180+ named exports; `/server` 7
(`renderToString`, `serializeState`, `readState`, `ServerDOMAdapter`, `STATE_MARKER_ATTR`,
`renderHead`, `VERSION`); `/testing` 25 (`render`, `findByRole`, `findByText`, `waitFor`,
`renderServerThenHydrate`, …).

---

## 1. API-reference listing (`API_GROUPS`) — all present

Every export the API page advertises exists:

- **Reactivity:** `signal`, `derived`, `effect`, `batch`, `resource` — all exported.
- **DSL:** `streetui`, `compile` — exported (`streetui.app(...)` method present).
- **Runtime & Renderer:** `createRuntime`, `createRenderer`, `BrowserDOMAdapter`,
  `ServerDOMAdapter` — all exported.
- **SSR:** `renderToString`, `serializeState`, `readState` — all exported (via `.` and
  `/server`).
- **Router:** `createRouter`, `mountRouter`, `routerOutlet`, `createBrowserHistory`,
  `createMemoryHistory` — all exported.
- **Testing:** `render`, `renderServerThenHydrate`, `findByRole`, `findByText`,
  `waitFor` — all exported from `/testing`.

No fabricated export. ✅

## 2. DSL builder methods documented in prose/samples — all present

Confirmed as real methods on the builder interfaces in the emitted type surface:
`section`, `container`, `heading`, `text`, `link`, `button`, `input`, `form`, `when`,
`listOf`, `code`, `head`, `portal`, and the overlays `dialog`, `popover`, `tooltip`,
`dropdown`, `toast` (each `(key, options, builder)`). Router methods `isActive(path,
options)` and `navigate(path)` are present; `ctx.params` / `ctx.query` are on the route
context. `component()`, `asyncBoundary`, `errorBoundary`, `mutation`, `defineConfig`,
`resetIdCounter`, the focus utilities, and the DevTools `createDevTools` / `inspect*` /
`renderDevToolsHTML` surface all exist. ✅

Note: `code` (documented as the `<pre><code>` primitive and used by the examples) exists
in the published surface — this is the F-1 finding from 2.5, resolved at the framework
level and now genuinely shipped. The site's claim that "every code snippet is real,
runnable StreetUI public API" holds.

## 3. One correction applied — prose implied a non-existent bare export

The Hydration doc section's prose read "**hydrate()** walks the existing server DOM …".
There is no top-level export named `hydrate`; the real public mechanisms are the
`hydrate: true` option on `mountRouter` and the `hydrateGraph` export. The API-reference
listing never claimed a `hydrate` export (it lists the real `renderServerThenHydrate`),
and no code sample called it — this was prose only. To keep "invent nothing" strictly
honest, the sentence was changed to: "Mounting with `hydrate: true` (mountRouter) — or
`hydrateGraph` for a single graph — walks the existing server DOM …". No test depended
on the old wording; the full website suite stays green (58/58).

## 4. Editorial (non-API) staleness — noted, not changed

- `CHANGELOG` tops out at **2.4.0**; the package building the site is **2.5.0** (and the
  2.6 release decision is still pending in Phase 10). This is editorial content, not an
  API claim, so it is **not** an "invent nothing" violation. The changelog should gain a
  2.5.0 (and, after the Phase 10 decision, 2.6.0) entry when the release is finalized —
  deferred to Phase 10 so the version is not implied before the gate passes.

## 5. Verdict

The website documents the framework it is built with, and — after the single prose
correction in §3 — **every documented API exists in the published package**. Nothing was
invented. Code-level API usage is additionally proven by `turbo run typecheck` (48/48):
had any builder/route code referenced a non-existent symbol, typecheck would fail.
