# StreetUI 2.4 — Solid competitor browser error: root-cause investigation

**Date:** 2026-09-30
**Status:** static-source root-cause **hypothesis** — **pending verification in the
authoritative (real-browser) environment.** I could not execute this in the
sandbox (no browser); the analysis below is from reading the adapter source, and
the proposed fix should be applied and verified where Chrome + the Solid toolchain
actually run. This note does **not** modify any file, so it cannot break the
currently-working scenario G.

Scope: this is a **dev-only benchmark adapter** issue
(`benchmarks/competitors/solid/`), not a StreetUI framework issue and not a
Solid framework bug.

---

## 1. Symptom

Solid browser scenarios A–E (and G's render path) fail with:

```
TypeError: Cannot read properties of undefined (reading 'done')
```

thrown from inside Solid's own compiled client bundle (`index-*.js`), while the
Node scenarios F (SSR) and H (bundle size) succeed. In 2.3 this left Solid with
no A–E/G browser numbers.

## 2. Root-cause hypothesis (high confidence, from source)

The Solid client bundle is compiled with **`hydratable: true`**:

`benchmarks/competitors/solid/vite.config.mjs:14`
```js
plugins: [solid({ hydratable: true, ssr: isSsr })],
```

With `hydratable: true`, `vite-plugin-solid` (babel-plugin-jsx-dom-expressions)
emits **hydration-aware template code**: the compiled `<Index>` / `<For>` /
`template()` calls read the hydration cursor from Solid's `sharedConfig.context`.

But scenarios **A, B, C, D, E all call `render()`**, not `hydrate()`:

`benchmarks/competitors/solid/src/scenarios.jsx` — e.g. line 51
(`render(() => <FlatList .../>, s.container)`), 95, 133, 165, 199.

`render()` does **not** establish a hydration context, so `sharedConfig.context`
is `undefined`. The hydratable-compiled template code then dereferences the
hydration cursor on that undefined context — i.e. `undefined.done` — which is
exactly `Cannot read properties of undefined (reading 'done')`.

Only scenario **G** calls `hydrate()` (line 224), which *does* set
`sharedConfig.context` — so G is the one path that would not hit this in a bundle
built for hydration. The failure signature (render-based A–E break; the error
lives in Solid's runtime, not the adapter code) matches this mechanism precisely.

**Conclusion:** the cause is **adapter/Vite configuration** — a single client
bundle compiled `hydratable: true` is used for both the `render()` scenarios
(A–E) and the `hydrate()` scenario (G). Hydratable output is only valid on the
hydrate path.

## 3. Proposed fix (adapter only; methodology unchanged)

Compile the `render()` scenarios **non-hydratable** and keep a **separate
hydratable** build only for the hydration scenario G — mirroring how the SSR
build is already gated by `VITE_SSR_BUILD`. No scenario logic changes; the
workloads stay identical and equivalent to the other frameworks.

`vite.config.mjs`:
```js
const isSsr = !!process.env.VITE_SSR_BUILD;
const hydratable = !!process.env.VITE_HYDRATABLE; // default false → valid for render()
export default {
  plugins: [solid({ hydratable, ssr: isSsr })],
  build: { minify: 'esbuild', target: 'es2022' },
};
```

Then in the orchestrator (`benchmarks/run-competitors.mjs`): build the default
client bundle (A–E) with `VITE_HYDRATABLE` unset, and build a second client
bundle for G with `VITE_HYDRATABLE=1`. Load the hydratable bundle only for the G
run (which already receives `globalThis.__SOLID_SSR_HTML__`).

Alternative (simpler, slightly less faithful for G): keep one non-hydratable
client bundle and mark G `SKIPPED` for Solid with the exact reason, since a
non-hydratable build cannot legitimately hydrate. The two-bundle approach is
preferred because it preserves G.

## 4. Verification checklist for the authoritative environment

1. Apply the `VITE_HYDRATABLE` gate above.
2. Build the A–E client bundle (non-hydratable) and confirm the `'done'`
   TypeError is gone and A–E produce real medians.
3. Build the G bundle (hydratable) and confirm `hydrate()` adopts the injected
   SSR markup with `domNodesCreatedDuringHydration ≈ 0`.
4. Re-run `benchmarks/run-competitors.mjs`; confirm Solid A–E + G now populate
   alongside React/Vue/Svelte, still with **no ranking emitted**.
5. Do **not** modify Solid source; if A–E still fail after the config gate,
   re-open the investigation (next suspects: Solid version interaction with
   `vite-plugin-solid`, or `sharedConfig` reset between `render()` disposals).

## 5. Honesty note

browser in the sandbox. It is offered for the authoritative environment to apply
