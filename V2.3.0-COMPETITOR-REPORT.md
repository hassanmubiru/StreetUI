environment and the same methodology** as React/Vue/Svelte/StreetUI, across
scenarios A–H. The measurement cannot be produced here for two independent,
empirical reasons:

1. **No browser.** Scenarios A, B, C, D, E, G run in a browser; no browser binary

Because the brief forbids modifying the shared methodology to make Solid pass,
forbids copying numbers from another source, and forbids placeholder results, the
only honest outcome is a reproducible BLOCKED state.

## Solid adapter — code-level finding (no methodology change)

The Solid adapter (`benchmarks/competitors/solid/`) is `present: true` with an
SSR entry defined in `competitors.json`. Its "no result file" outcome cannot be
attributed to a specific runtime bug from here, because the adapter has **never
been executed** in this environment — there is no browser to run the in-page
scenarios and no registry to install `solid-js`. Diagnosing *why Solid produces
no result* is therefore itself BLOCKED: any claim of a root cause would be
speculation. What can be stated: the failure is not a StreetUI defect, and the
shared A–H methodology and `streetui-2.2-competitors/v1` schema are intact and
were not altered.
