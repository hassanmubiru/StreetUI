## 1. What shipped

A production-grade interaction layer built **entirely on the existing pipeline** —
no virtual DOM, no second renderer, no second reactive system, no framework
compat layer, and no package fragmentation. Everything lands in the existing
internal packages (`core`/`dom`/`dsl`/`renderer`/`devtools`/`testing`) which are
re-exported by the single public `streetui` package (`.` / `./server` /
`./testing`). No public `@streetui/transition|a11y|focus|overlay` package exists.

### Transitions & animation (§2–§8)
- CSS class-based transition engine (`enter-from/-active/-to`, `leave-*`), no
  WAAPI, no browser API at module scope. Browser-only: every operation is a
  no-op when `dom.body() === null`, so SSR output is unchanged.
- `__transition__<id>` descriptor registered at compile time via the handler
  registry (same pattern as `__overlay__`/`__component__`) and pruned by
  `graph._unregisterNodeHandlers` on detach.
- Leave-deferral: the reconciler's remove → dispose → forget → detach chain is
  deferred to animation end; a re-entering key reclaims the same live node
  (leave→enter cancellation). Full cancellation matrix covered.
- Wired into list items (`itemTransition`), `when()` branches, overlays, and
  router navigation without rewriting any of those subsystems.

### Router & overlay transitions (§9–§10)
- Router cross-fade: incoming route mounts into its own `data-streetui-route`
  host and enters; outgoing route disposal is deferred to leave-end. Initial
  mount/hydrate is never animated (§22). Rapid navigation cancels the departing
  host's in-flight enter. The original synchronous path is byte-for-byte
  unchanged when no `transition` option is supplied.
- Overlays inherit transitions for free (the panel's `when(open)` branch carries
  the transition). Focus is restored at close-*request* time, so a panel
  animating out never keeps focus.

### Accessibility & focus (§11–§18)
- Deterministic `a11yIds(base)` extended with `trigger`/`controls`/`owns`
  relationship ids — pure derivation, byte-identical server↔client.
- Dialog keyboard (§12): trap Tab/Shift+Tab with wrap, contain escaped focus,
  focus-in on open (disabled skipped), Escape to close, restore on close. Nested
  modals compose via a module-level containment stack (§16) — only the top
  container enforces containment; cleanup pops it.
- Menu keyboard (§13): `rovingMenu` (Arrow/Home/End/Enter/Space, re-queries items
  each key so disabled/reactive items stay live), wired only for `role="menu"`.
- Live regions (§15): `createAnnouncer(dom)` keeps exactly one polite + one
  assertive region, mutates text to speak (clear-then-set on a microtask so
  repeats re-announce), reuses nodes (no stale pile-up), SSR-inert.
- Interaction state (§18): app-owned signals/derived; no transient state on graph
  nodes — runtime bookkeeping lives in controllers/closures torn down on cleanup.
- §11 conformance doc is honest: **no** WCAG/ARIA-APG universal-compliance claim;
  the browser/AT gate is BLOCKED, not simulated.

### DevTools & testing (§19–§20)
- `inspectInteractions(graph)` — prod-safe: walks the graph and reads only the
  `__overlay__`/`__transition__` descriptors + public node structure, peeks
  `open` without subscribing, retains no DOM, mutates nothing. Reports overlays
  (open/modal/takesFocus/menu/closeOnEscape/restoreFocus/depth) and transitions
  (nodeType/duration/appear/depth).
- Testing helpers: `focus`/`blur`/`pressKey`/`clickOutside`/`openOverlay`/
  `closeOverlay`/`waitForTransition`, built on existing `trigger`/`flushUpdates`.
  `waitForTransition` dispatches the `transitionend` the controller listens for
  (happy-dom fires none) then flushes deferred leave-teardown; `clickOutside`
  throws on an inside target rather than silently no-op'ing.

## 2. Production-hardening evidence (§21–§29)

- **§21 SSR determinism.** Transitions are browser-only; server output carries no
  transition/appear/live-region classes. `scripts/verify-ssr-hashes.mjs` **PASS**
  on all 5 routes — byte-length and SHA-256 identical to the v1.6 baseline:
  overview `19d86cbb` (730B), dashboard `4f6b4a39` (925B), users `f8f20c0d`
  (3,610,699B), controls `3616bce9` (36,551B), settings `42127b6f` (926B).
- **§22 Hydration.** Hydration adopts server DOM in place and never replays the
  `appear` enter animation; a control fresh-mount does play it, proving the
  contrast (`transition.test.ts`).
- **§23 Handler pruning.** `__transition__<id>` is added to the detach prune list;
  memory tests assert the registry drains to baseline (and to 0 after unmount).
- **§24 Browser/AT.** BLOCKED — no Chromium/Playwright available. **Not faked.**
- **§25 No breaking changes.** Every new export is additive; the frozen v1.0
  surface is untouched; per-package stability tests only assert presence.
- **§26 Memory stress.** Grow→enter→leave of 50 / 100 / 200 transitioned items:
  the instance index and `__transition__` handler registry return exactly to
  baseline after enter+leave settle, and to ≤1 / 0 after unmount — no controller,
  listener, timer, or handler leak.
- **§27 Single package.** No fragmentation: `inspectInteractions` reaches the
  public API via `streetui` (`export * from '@streetui/devtools'`); the testing
  helpers via `streetui/testing`. No new public packages.
- **§28 Version.** Stamped **1.9.0** across 18 package.json files, `version.ts`
  (`VERSION`), `cli` (`CLI_VERSION`), and the two stability/public tests that
  assert the version. Release-artifact files that require a real `npm pack`/
  publish (dist-tarballs / release-manifest) were deliberately left untouched —
  see §3.
- **§29 Component integration.** A `component()` that owns a transitioned
  `when()` panel driven by a prop signal enters on open, defers leave on close,
  and runs its cleanup exactly once when the whole component unmounts.
