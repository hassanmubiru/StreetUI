## 3. v1.4 changes (internal only, no public API changes)

### 3.1 SSR serializer optimisation (`packages/dom/src/server-node.ts`)

**What changed:** Fast-path early return in `escapeHtmlText` and `escapeHtmlAttr`
skips allocation when no special character (`&<>"'`) is present — the overwhelmingly
common case in real content. `SERIALIZED_PROPERTY_ENTRIES` hoisted to module
scope (was re-allocated ~80k times per 10k-row SSR render).

**Measured effect — deterministic same-process A/B (serialize phase only):**

| | Median |
|---|---|
| Pre-v1.4 serializer replica | 103.9 ms |
| v1.4 shipped serializer | 64.1 ms |
| Speedup | **1.62×**, output byte-identical |

SSR is mount-dominated (mount ~62%, serialize ~33%). The mount phase (shared
renderer) was not changed. The full end-to-end `renderToString` cross-run median
varies 184–233 ms on this 2-core VM — too noisy to quote as a percentage. The
serialize A/B is the reported figure.

**Byte-identity gate (SSR contract preserved):** all five route bodies
sha256-identical before/after.

### 3.2 `/* @__PURE__ */` singleton annotations (`packages/dom/src/`)

**What changed:** `serverDOMAdapter` and `browserDOMAdapter` convenience singletons
annotated `/* @__PURE__ */`. The exports are unchanged (frozen API intact); only
the unused singleton initialisers become droppable by esbuild tree-shaking.

**Measured bundle impact (esbuild, bundle+minify+treeShake, gzip):**

| Profile | v1.3 gzip | v1.4 gzip | Δ |
|---------|-----------|-----------|---|
| minimal (reactivity + client render) | 8,606 B | 7,619 B | **−987 B (−11.5%)** |
| typical (router/forms/i18n/store/resource) | 15,365 B | 14,377 B | **−988 B (−6.4%)** |
| real app entry | 15,690 B | 14,667 B | **−1,023 B (−6.5%)** |
| full (`import *`, retains SSR) | 20,105 B | 20,205 B | +100 B (+0.5%) |

The full-barrel profile legitimately includes `renderToString` and retains the
serializer — its +100 B is the serializer fast-path code, disclosed and expected.
Client bundles that don't import SSR shrink ~1 KB gzip.
