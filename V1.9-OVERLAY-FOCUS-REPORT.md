## 1. What was built

A production overlay/focus platform assembled **entirely from existing
primitives** (§22) and shipped **inside the single `streetui` package** (§23 —
no `@streetui/portal|a11y|components` fragmentation).

### 1.1 Portal primitive (§19/§20)

`ContainerDSL.portal(key, builder, options?)` introduces exactly **one** new
semantic node type, `'portal'`, and **no new render path**:

- **Browser mount:** the portal creates an inline anchor `[data-streetui-portal]`
  at the declaration site, then mounts its children into a fresh body-level
  container `[data-streetui-portal-container]` appended to `document.body`. The
  anchor is left empty inline. Cleanup (tracked on the NodeInstance) removes the
  body container on unmount — no orphaned DOM.
- **Server (SSR):** `dom.body()` is `null`, so children render **inline** in the
  anchor. The body-relocation is a browser-only concern; the server emits no
  `[data-streetui-portal-container]` marker.
- **Hydration:** the server-inline children are relocated from the anchor into a
  fresh body container **before** positional child adoption, so the live tree
  matches the browser mount path exactly and there is no positional mismatch.

Portals are **excluded from static-subtree classification** in the compiler
(`analyzeGraph`), so they always take the real mount/hydrate branch and never
collapse into serialized raw HTML.

### 1.2 Overlay system (§5)

`dialog` / `popover` / `tooltip` / `dropdown` / `toast` are each the same
composition: a **portal** + a **`when(open, …)` panel** + focus/keyboard
behavior wired from an `__overlay__<portalId>` descriptor registered through the
**existing handler registry** (the same mechanism as `__signal__` /
`__listbuild__` / `__listplan__`). The renderer reads the descriptor with a
local structural type — no dsl→renderer dependency.

| kind     | role    | aria-modal | takes focus | focus trap+contain | Escape closes | restore focus | aria-live |
|----------|---------|------------|-------------|--------------------|---------------|---------------|-----------|
| dialog   | dialog  | yes        | yes         | yes                | yes           | yes           | —         |
| popover  | dialog  | no         | yes         | no                 | yes           | yes           | —         |
| dropdown | menu    | no         | yes         | no                 | yes           | yes           | —         |
| tooltip  | tooltip | no         | no          | no                 | no            | no            | —         |
| toast    | status  | no         | no          | no                 | no            | no            | polite    |

`open` is **app-owned**; the framework never mutates it. Closing is
**cooperative**: `onClose` fires on Escape (when `closeOnEscape`) and the app
flips its own `open` signal there. Per-kind defaults are overridable via options.

**Subscription-ordering correctness:** the panel's inner `when()` subscribes to
`open` (via the reactive-list machinery) **before** `wireOverlayBehavior`
subscribes, because the conditional child is mounted before overlay wiring runs.
So on `open→true` the panel DOM exists before focus moves into it, and on
`open→false` the panel tears down before focus is restored.

### 1.3 Focus utilities (§6) — `streetui/dom`

`saveFocus`, `restoreFocus`, `focusInitial`, `trapFocus`, `containFocus`,
`onEscape` (added to the frozen value-export surface), plus
`body`/`activeElement`/`contains`/`matches` DOM-adapter environment methods.
All go through the `DOMAdapter`, so they are SSR-safe no-ops on the server.

## 6. Public API additions (all inside `streetui`)

```ts
container.portal(key, builder, options?);            // PortalOptions
container.dialog(key, options, builder);             // OverlayOptions (open required)
container.popover(key, options, builder);
container.tooltip(key, options, builder);
container.dropdown(key, options, builder);
container.toast(key, options, builder);
```

`OverlayOptions`: `open` (required, Bindable<boolean>), `onClose?`,
`restoreFocus?`, `initialFocusId?`, `closeOnEscape?`, plus the shared
`ContainerOptions`/`A11yOptions` (now including `ariaModal`).

From `streetui/dom`: `saveFocus`, `restoreFocus`, `focusInitial`, `trapFocus`,
`containFocus`, `onEscape`, `FOCUSABLE_SELECTOR`, `focusById`, `focusFirst`,
`getFocusable`.
