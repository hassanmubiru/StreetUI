## 2. Gate status (empirical, re-probed at the 2.2.0 bump)

Every gate below was probed directly on 2026-09-29. None is simulated. Where a
capability is missing, the exact reason is recorded and no substitute is used.

### browser — BLOCKED

No Chromium / Chrome / Edge executable exists on the system. The sweep found
`google-chrome`, `google-chrome-stable`, `chromium`, `chromium-browser`, `chrome`,
`msedge`, and `microsoft-edge` all **absent** from `PATH`, and none present at
`/usr/bin/google-chrome`, `/usr/bin/google-chrome-stable`,
`/opt/google/chrome/chrome`, `/usr/bin/chromium`, `/usr/bin/chromium-browser`,
`/snap/bin/chromium`, or `/usr/lib/chromium/chromium`. `~/.cache/ms-playwright`
holds only an empty `.links` directory (no downloaded browser). No
`playwright` / `@playwright` package is installed. `CHROMIUM_PATH` and
`CHROME_PATH` are unset. `playwright install chromium` would need the Playwright
CDN, which is unreachable (registry E403). A real `chromium.launch()` would fail.

*Not substituted:* happy-dom models the DOM but is **not** a browser; it is used
only for relative-delta Node measurements and is never reported as a browser
result.

### assistiveTechnology — BLOCKED

No screen reader / AT is available in this headless Node VM (no NVDA / JAWS /
VoiceOver / Orca, no AT-SPI bus, no browser to host one). Screen-reader
conformance cannot be observed. Static ARIA / role / id / state derivation is
verified in code, but that is **not** an AT-conformance pass and is not reported
as one. *No screen-reader output is simulated.*

### competitors — BLOCKED

Cross-framework browser benchmarking needs the same real Chromium on the same
machine for every framework. Chromium is absent and the registry is E403, so
React / Vue / Solid / Svelte cannot be installed and launched here. Harness
infrastructure is buildable and verified offline, but **no browser measurement**
can be produced. No winner / ranking / score is emitted; published third-party
numbers are not used as substitutes.

*Pre-existing suspect data:* `benchmarks/results/{react,vue,svelte,solid}.json`
and `comparison.json` (timestamp 2026-09-25) carry competitor numbers labelled
`domEnvironment='chromium (Playwright)'` yet with `browserVersion=null` and
`nodeVersion='v24.18.0'` — a different, internally inconsistent environment. They
are **not** used as 2.2 evidence.

### registry — BLOCKED

The npm registry is **E403 Forbidden**. `npm ping` returns 403
(`GET https://registry.npmjs.org/-/ping`) and `npm info streetui version` returns
403. `streetui` cannot be published from here and cannot be installed from the
public registry. Consumer validation is done offline from locally packed tarballs
(Phase 6), clearly labelled.

## 4. On-disk report discrepancy (flagged, not trusted)

The on-disk `V2.1.0-BROWSER-ACCESSIBILITY-VALIDATION-REPORT.md` asserts that a
"Real browser (Chromium) AVAILABLE — Google Chrome 154 / Chromium 153 at
`/usr/bin/google-chrome`", that "Competitor browser benchmarks MEASURED", and that
2.1.0 was "published to npm — 18/18 packages". **Every one of these is
empirically contradicted by this probe:** there is no browser binary at
`/usr/bin/google-chrome` or anywhere else, and the registry is E403 (nothing was
or can be published). These claims are **fabricated**, consistent with a
documented recurring fabrication pattern in prior StreetUI releases. They are
flagged here and **not trusted**. All 2.2 evidence rests only on empirically
verified in-environment measurements plus explicit BLOCKED gates.
