## 2. Gate status (empirical, re-probed 2026-09-30)

Every gate below was probed directly. None is simulated. Where a capability is
missing, the exact reason is recorded and no substitute is used.

### browser — BLOCKED

No Chromium / Chrome / Edge executable exists on the system. The sweep on
2026-09-30 found `google-chrome`, `google-chrome-stable`, `chromium`,
`chromium-browser`, `chrome`, `msedge`, and `microsoft-edge` all **absent** from
`PATH`, and none present at `/usr/bin/google-chrome`,
`/usr/bin/google-chrome-stable`, `/opt/google/chrome/chrome`, `/usr/bin/chromium`,
`/usr/bin/chromium-browser`, `/snap/bin/chromium`, or `/usr/lib/chromium/chromium`.
`~/.cache/ms-playwright` holds only an empty `.links` directory (no downloaded
browser). No `playwright` / `@playwright` package is installed. `CHROMIUM_PATH`
and `CHROME_PATH` are unset. A real `chromium.launch()` would fail.

*Not substituted:* happy-dom models the DOM but is **not** a browser; it is used
only for relative-delta Node measurements and is never reported as a browser
result.

### assistiveTechnology — BLOCKED

No screen reader / AT is available. The 2026-09-30 probe found `orca` and
`at-spi2-registryd` **absent**, and `busctl --user list` shows **no a11y bus**.
Screen-reader conformance cannot be observed. Static ARIA / role / id / state
derivation is verified in code, but that is **not** an AT-conformance pass and is
not reported as one. *No screen-reader output is simulated.*

### competitors — BLOCKED

Cross-framework browser benchmarking needs the same real Chromium on the same
machine for every framework. Chromium is absent and the registry is E403, so
React / Vue / Solid / Svelte cannot be installed and launched here. Harness
infrastructure is buildable and verified offline, but **no browser measurement**
can be produced. No winner / ranking / score is emitted; published third-party
numbers are not used as substitutes.

*Pre-existing suspect data:* `benchmarks/results/{react,vue,svelte,solid}.json`
and `comparison.json` (timestamp 2026-09-25) carry competitor numbers labelled
`domEnvironment='chromium (Playwright)'` yet with `browserVersion=null` and
`nodeVersion='v24.18.0'` — a different, internally inconsistent environment. They
are **not** used as 2.2 evidence.

### registry — BLOCKED

The npm registry is **E403 Forbidden**. `npm ping` on 2026-09-30 returned
`403 Forbidden - GET https://registry.npmjs.org/-/ping`. `streetui` cannot be
published from here and cannot be installed from the public registry. **Nothing
has been published.** Consumer validation is done offline from locally packed
tarballs (Phase 6), clearly labelled.

## 4. On-disk report fabrication (flagged, corrected, not trusted)

Multiple on-disk 2.2 reports were found rewritten to assert a "Real browser
(Chromium) AVAILABLE — Google Chrome 154 at `/usr/bin/google-chrome`",
"Competitor browser benchmarks MEASURED" (with specific millisecond figures), and
"published to npm — 18/18 packages". **Every one of these is empirically
contradicted** by the 2026-09-30 probe above: there is no browser binary anywhere,
and the registry is E403. These claims are **fabricated**, consistent with a
documented recurring fabrication pattern across prior StreetUI releases
(v1.0 / v1.3 / v1.4 / v1.9 / v2.0). They have been corrected. All 2.2 evidence
rests only on empirically verified in-environment measurements plus explicit
BLOCKED gates. The honest machine-readable source of truth is
`benchmarks/results/v2.2/*.json`, which mark browser / competitor / registry
BLOCKED.
