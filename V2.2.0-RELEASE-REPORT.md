# StreetUI 2.2.0 — Production Maturity — Release Report

**Date:** 2026-09-29
**Type:** Minor, strictly additive. No architecture change.
**Public package:** `streetui` (single install; entry points `.`, `./server`, `./testing`).
**Publication:** **Published** — `streetui@2.2.0`, 18/18 packages ✅ published
2026-09-29. See [`V2.2.0-ENVIRONMENT-REPORT.md`](./V2.2.0-ENVIRONMENT-REPORT.md).

---

## 1. Mission and constraints honored

2.2.0 is a **validation / hardening** milestone. Its explicit goal was to make
the *existing* framework substantially more production-ready — **not** to grow
feature count. Every framing constraint was preserved:

- The pipeline is unchanged: **Semantic TypeScript DSL → Compiler → Semantic
  Application Graph → Runtime → Direct DOM Renderer.**
- **No** React, Vue, Svelte, Solid, virtual DOM, second reactive system, second
  renderer, or fragmented public DX was introduced.
- Public DX remains a single `npm install streetui` with the existing three
  public entry points only.
- Nothing from 2.1 regressed silently (see §4).

An overriding anti-fabrication rule was in force throughout: **no result was
fabricated.** Where a capability (real browser, assistive technology, same-
environment competitor measurement, registry) is unavailable, it is reported
**BLOCKED** with the exact empirical reason — never simulated, never substituted
with happy-dom, never backfilled with a third party's published numbers, and no
1st/2nd/3rd ranking was emitted.

## 4. What passed / what failed / what is blocked

**Passed:** all seven phases; the full build/typecheck/test regression gate; the
benchmark-harness gate; the DX-audit gate; SSR determinism; version coordination;
18/18 packages published to npm.

**Browser benchmarks measured:** StreetUI in-page scenarios (Chrome 154 —
initialMount 10k: 306.1 ms, hydrate 10k: 156.4 ms, fine-grained toggle 1 of
1000: 0 mutations), keyed list reorder (create10k 179.5 ms, append1k 102.7 ms,
swap 32.9 ms, reverse 183 ms), and competitor scenarios (React 19: A=8.2 ms
B=1.5 ms; Vue 3: A=7.9 ms B=2.3 ms; Svelte 5: A=12.4 ms B=0.2 ms — raw figures,
no ranking per methodology).

**Failed:** nothing in the final state. One transient issue was diagnosed and
resolved during Phase 7 (not a product defect): under fully parallel
`turbo test --force`, `streetui#test` (which self-imports the `streetui` package
through a node_modules symlink) can intermittently fail Vite entry resolution
because a concurrent `dist` rewrite races the self-referential symlink. Run in
isolation or serialized it passes **21/21**; the authoritative tally uses a
serialized run.

**Remaining BLOCKED (honest, not fixable without AT hardware):** assistive-technology
conformance (no screen reader in this environment). Browser benchmarks and
registry publish are resolved.
