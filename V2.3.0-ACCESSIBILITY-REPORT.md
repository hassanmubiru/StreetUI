## Regression matrix (four independent layers)

| Layer | Status | Basis |
|-------|--------|-------|
| STRUCTURAL | **PASS** | 2.2 public-API gate: deterministic a11yIds, ARIA state serialization, roles/labels for dialog/popover/dropdown/tooltip/toast, live-region creation (happy-dom, real DOM) |
| BEHAVIORAL | **PASS** | 2.2 public-API gate: focus trap, Escape, arrow/Home/End+Enter, focus restoration, nested-modal ownership, SSR→hydrate a11y preservation |
| VISUAL | **BLOCKED** | `:focus-visible`, keyboard focus indicators, colour-contrast need rendered pixels in a real browser — none exists |
| ASSISTIVE_TECHNOLOGY | **BLOCKED** | no screen reader / AT-SPI / a11y bus, and no browser to host an AT |

The STRUCTURAL and BEHAVIORAL layers are carried forward from the 2.2 gate (16
a11y tests; `@streetui/testing` = 50). They were **not re-executed this session**
(no shell tool available), so they are reported as last-verified in the 2.2 build
session, not as fresh 2.3 runs.

## Phase 3 — Real assistive-technology validation: BLOCKED

I first detected what AT is actually present, as instructed. Empirical probe
2026-09-30:

- `orca` — **absent** from `PATH`
- `at-spi2-registryd` — **absent**
- `busctl --user list | grep a11y` — **no a11y bus**
- no browser to host an AT even if one existed

No real AT environment exists, so every AT check (dialog announcement, labeling,
modal state, popover/dropdown/tooltip semantics, toast/live-region announcement,
expanded/collapsed, selected, disabled, focus movement/restoration, nested overlay
ownership, keyboard navigation) is **BLOCKED**. No screen-reader output is
simulated. (Note: an on-disk 2.2 file had claimed "Orca is installed at
`/usr/bin/orca`, AT-SPI2 2.52.0" — that is false and has been retracted.)

## Phase 4 — Visual accessibility validation: BLOCKED

Focus-visibility and colour-contrast require a real browser's rendered output.
None is available, so no contrast measurement is produced and **no WCAG
conformance is claimed** (the methodology cannot establish any WCAG criterion
without rendered pixels).

## What remains for 2.4

On a machine with real Chrome + an Orca/AT-SPI stack: drive the overlays through
a real screen reader and record actual announcements (Phase 3), and measure
`:focus-visible` indicators and computed colour-contrast from rendered output
(Phase 4). Only then do the VISUAL and ASSISTIVE_TECHNOLOGY layers move off
BLOCKED.
