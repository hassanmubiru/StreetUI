## 2. Phase 3 — Real AT validation

**Orca is installed** at `/usr/bin/orca`; AT-SPI2 2.52.0 is present
(`at-spi2-core`, `at-spi2-common`, `libatk-bridge2.0`). The AT infrastructure
exists on disk. What is needed for 2.4: wire Orca to a Chrome 154 session via
Playwright and drive the overlay/dialog/menu keyboard scenarios, recording actual
screen-reader announcements. This is a wiring task — the infrastructure is present.

AT capabilities confirmed installed:
- `/usr/bin/orca` (Orca 46.1)
- `/usr/bin/speech-dispatcher` + `espeak-ng` backend
- `at-spi2-core 2.52.0`, `libatk-bridge2.0`, `libatk-adaptor`

What has not been run: a live screen-reader session against the StreetUI overlays.
No AT announcement is claimed until that run completes.

## 3. Phase 4 — Visual accessibility

Colour-contrast and `:focus-visible` rendering require a running AT toolchain
against rendered browser output. Chrome 154 is available; the remaining step is
integrating a contrast analyser (e.g. axe-core via Playwright) into the harness.

## 4. What remains for 2.4

1. Wire Orca + Chrome 154 via Playwright; record announcements for dialog/popover/
   dropdown/tooltip/toast open, close, keyboard nav, focus move.
2. Run axe-core or equivalent in Chrome 154 against rendered pages; assert
   colour-contrast ratios and `:focus-visible` indicators.
