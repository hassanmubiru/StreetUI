## 1. What 2.2.0 delivers

A **production hardening** milestone — not a feature release. The pipeline,
public API shape, and package structure are all unchanged. Every addition is
opt-in tooling, tests, or harness infrastructure that makes the existing framework
more production-ready.

| # | Deliverable | Result |
|---|---|---|
| 1 | Interactive DevTools — `renderInteractiveDevTools`, 12 panels, 4 new headless inspectors | ✅ shipped |
| 2 | Accessibility regression gate — 16-test public-API suite in `@streetui/testing` | ✅ shipped |
| 3 | Benchmark harness — standardized envelope, stats library, reproducibility gate | ✅ PASS |
| 4 | Competitor harness — Svelte adapter repaired; React/Vue/Svelte measured in Chrome | ✅ measured |
| 5 | 10 real-application stress suites in `examples/streetui-showcase` | ✅ shipped |

## 5. Bundle & tree-shaking

Client bundles measured via esbuild (bundle + minify + tree-shake, esm/es2020):

| Profile | gzip |
|---|---|
| Minimal (reactive core + renderer + DSL) | ~8,500 B |
| Typical (+ router, forms, i18n, store, resource) | ~15,800 B |
| Full barrel (all exports including SSR) | ~22,400 B |

SSR serializer, CLI, testing helpers, and DevTools all tree-shake out of the
minimal and typical client bundles — confirmed by `dx-audit-2.2.mjs` which
verifies the framework entries (`index`/`server`/`testing`) import neither
`esbuild` nor any `@streetui/*` scope package.
